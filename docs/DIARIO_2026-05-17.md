## API Base URL e Cache Busting

Foi ajustado o `api.js` para funcionar melhor em local e em producao.

Ponto importante:

```js
const API_BASE_URL = globalThis.HOUSEHOST_API_BASE_URL || resolveApiBaseUrl();
```

Com isso:

```text
se HOUSEHOST_API_BASE_URL existir, usa a URL definida manualmente
se nao existir, resolve automaticamente a base da API
```

Tambem foi usado cache busting nos imports:

```js
import { login } from "../api.js?v=2026-05-17-01";
```

Isso foi documentado em:

```text
docs/CACHE_BUSTING_FRONTEND.md
```

Objetivo:

```text

quando o arquivo antigo pode estar preso no cache
```

## Heranca em Transacoes Financeiras

Criamos heranca JPA usando:

```java
@Inheritance(strategy = InheritanceType.JOINED)
```

Modelo escolhido:

```text
tabela mae -> financial_transactions
tabela filha -> installment_plan_transactions
tabela filha -> installment_transactions
```

Classes filhas:

```text
InstallmentPlanTransaction
InstallmentTransaction
```

`InstallmentPlanTransaction` representa uma transacao parcelada.

Ela recebe:

```text
installmentsQuantity
installmentPlanStatus
```

E instancia automaticamente as parcelas.

`InstallmentTransaction` representa uma parcela individual.

Ela guarda:

```text
installmentPlan
installmentNumber
totalInstallments
installmentStatus
```

## Parcelamento na Reserva

No formulario de reserva:

```text
A vista
2x
3x
Entrada + saldo no check-in
```

No backend:

```text
A vista -> FinancialTransaction normal
2x / 3x / entrada + saldo -> InstallmentPlanTransaction
```

O metodo que decide isso fica em:

```java
BookingService.createPaymentTransactionIfPresent(...)
```

Regra:

```text
installmentsQuantity > 1 -> transacao parcelada
installmentsQuantity == 1 -> transacao normal
```
